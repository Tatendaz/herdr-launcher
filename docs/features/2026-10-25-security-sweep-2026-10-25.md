# Feature: Pin workflow actions to commit SHAs

**Branch:** security/sweep-2026-10-25
**Date:** 2026-10-25

## Summary
Pins every `actions/checkout` and `actions/dependency-review-action` use to a
full commit SHA, and stops the checkout step from leaving the token on disk.

## Motivation
`pr-gate.yml` and `dependency-review.yml` used mutable tags (`@v4`, `@v5`). If
an action's tag is moved to bad code, every PR run picks it up. `zizmor`
flagged 5 unpinned uses and 4 checkouts with `persist-credentials` left on.

## What changed
- `pr-gate.yml`: the three `actions/checkout@v4` steps now use the v4.4.0 SHA
  with `persist-credentials: false`. Same major version, so no behavior change.
- `dependency-review.yml`: `actions/checkout` pinned to the v7.0.1 SHA the
  owner's other repos use, `actions/dependency-review-action` pinned to the
  v4.9.0 SHA (what `v4` pointed to), and `persist-credentials: false`.

## Notes
The coverage job's `git fetch origin` still works without stored credentials,
because the repo is public.
